# NGA IM Tools
This document attempts to list and describe all of the systems and tools in use for Information Management at the NGA LTER site.

## The Research Workspace
The Research Workspace (or 'the Workspace', or 'the RW') is an online data management platform developed and used by Axiom Data Science. The Workspace provides secure and redundant file storage, multiple levels of user permissions, an inegrated metadata editor for writing ISO 19115/19139 compliant metadata, and configurable connections to Axiom's data portals and the Research Workspace DataONE Member Node.

The NGA LTER site uses the Research Workspace to:
- store and share data within the program,
- to pass data the information manager to be archived,
- to author metadata, and
- to submit datasets to be archived in the RW DataONE Member Node. 

All site personel have access to the RW, and members with sufficient permissions can add and remove members. All of these activities occur within the *Northern Gulf of Alaska Long Term Ecological Research Site (NGA LTER)* campaign in the Workspace. Within the campaign are dozens of projects, each representing a data type or collection effort. Each member of the NGA campaign has some access to all the projects in the campaign. Adding members to individual projects and not to the campaign prevents them from seeing or accessing other projects in the campaign. 
All members with sufficient priviliges can upload data into the Workspace from their browser, author metadata in the integrated editor, or download files.

Each NGA project contains a `Data/` folder that has an `Archive/` subfolder and one or more other subfolders for each type of dataset generated by the project. The `Archive/` subfolder contains one subfolder for each dataset that has been archived from the project, with each of these folders containing the data files and metadata that were sent to the repository for the most recent edition of the archived dataset. Only the site IM should move files into the `Archive/` folder or its subfolders, and they should only do so once the files have been reviewed and are ready to be archived. Other subfolder of the `Data/` folder should be organized by year and data processing level. Data levels are discussed and agreed upon with the scientists and techinians responsible for the data as early as possible, often while drafting a DMP for the dataset. 

For more details on the Research Workspace see https://researchworkspace.com/help/.

## Metadata Editors
### The Research Workspace Metadata Editor
It's built into the Workspace and creates json-formatted content that gets exported in ISO 19115/19139 compliant metadata records when datasets are prepared to be archived.
### ezEML
https://ezeml.edirepository.org/  
A web-based editor developed by the folks at EDI to make it easy to write EML. Sign in with the im.ngalter@gmail.com account or create a personal account. Records can be shared with other users for collaborative writing and review. 
## Repositories
### The Research Workspace DataONE Member Node
The Research Workspace DataONE Member Node (RWd1MN) is an implementation of the DataONE Generic Member Node on storage resources in Axiom's data center in the Pittock Internet Exchange in Portland Oregon. All contents of RWD1MN are backed up within the data center, and copied offsite via Backblaze nightly.  
### EDI
Ecological Data Initiative Data Repository (https://edirepository.org/). Most of the other LTER data is here. NGA has been archiving data since Spring 2025, beginning with new or one-off datasets. Ongoing data that are currently archived in the Research Workspace DataONE Member Node will remain there until the data from the final year of the NGA Phase II funding period have been archived. Beginning in Phase III, all NGA datasets will be archived in EDI.

## Data Portals
### NGA LTER Data Portal
The [NGA LTER Data Portal](https://search.dataone.org/portals/NGALTER) uses the the DataONE Custom Portal service to searh DataONE holdings to find all datasets associated with the NGA LTER site that have been archived in a DataONE Member Node. We are not aware of any datasets that been archived in a repository that is not a member node, so this should be comprehensive.

### AOOS Ocean Data Explorer

Results from NGA's modeling component are made available as interactive visualizations and downloadavble netCDF files in the Alaska Ocean Observing System's [Ocean Data Explorer](https://aoos.org/ocean-data-explorer/) (or ODE). The ODE contains thousands of other marine data layers, real-time and historical sensor streams, and customized dashboards.

## Jira and Confluence
### Jira
Axiom uses Jira, an issue tracket from Atlassian, internally for task management and project management. All of the NGA LTER datasets and IM tasks are represented as tickets on Jira boards. Each ticket lists the metadata required, ultimate repository where the dataset will be preserved, when the data is expected, the location where the data should be in the Research Workspace, and the estimated effort for curating the dataset and upating the archive. Emails between IM the PIs can be forwarded to these tickets to keep dataset context attached to the ticket. 
### Confluence
Conflunece is an Atlassian knowledge management system that integrates with Jira. In Confluence, each data type has a page providing dataset context and a running work journal to provide a narrative of current and historical work to curate the dataset. 
Dataset context includes:
 - Project
 - PI
 - Other important contacts
 - Research Workspace link
 - Jira issue template (for annual datasets)
 - Links to all Jira tickets associated with the dataset
 - The DOI or DOIs associated with dataset
 - Links to other important context, e.g. github repos or project websites
